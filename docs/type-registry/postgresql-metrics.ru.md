# Класс 1: снимки PostgreSQL

[English version](postgresql-metrics.md)

Секции метрик PostgreSQL занимают диапазон `1_001_001`–`1_020_001`. Точные
столбцы, единицы, ключи и семантика объявлены в
[`crates/kronika-registry/src/codec`](../../crates/kronika-registry/src/codec).
В этом справочнике указано, какая версия сервера или расширения выбирает каждый
формат.

## Граница сбора

Коллектор читает один настроенный инстанс PostgreSQL: первую запись в
`KRONIKA_PG_DSNS`. Строки метрик не содержат `system_identifier`.

Для системных представлений формат выбирается по основной версии PostgreSQL.
Представления, привязанные к базе, читаются из каждой доступной для подключения
базы этого инстанса. Если источник отсутствует, не поддерживается или не
читается, при этом чтении секция не создаётся.

Для PostgreSQL 14–18 секция `pg_stat_activity` типа `1_001_004` сохраняет
nullable-поле `datid` непосредственно из системного представления рядом с
`query_id`. Для общих и фоновых процессов OID базы остаётся `null`.
Идентичность строки Activity по-прежнему задаёт PID; OID используется только
как предикат перехода к связанным верхнеуровневым строкам
`pg_stat_statements` и никогда не выводится из имени базы.

Коллектор сохраняет исправное соединение с каждой базой между циклами сбора.
Базы и расширения обнаруживаются примерно раз в пять минут. Для появившейся
базы открывается соединение, для удалённой — закрывается.

При обнаружении расширений в каждой базе один раз читается инвентаризация. Она
содержит базу, схему и доступные интерфейсы каждой установки.
`pg_stat_statements` и `pg_store_plans` показывают счётчики всего инстанса,
поэтому коллектор читает по одной пригодной установке каждого расширения и не
дублирует общие строки. Расширение можно создать, удалить или перенести в другую
базу либо схему; при следующем обнаружении выбирается новое расположение. Если
поддерживаемой установки нет, её секции отсутствуют.
Каждое доступное представление info выбирается независимо от основной функции
чтения расширения.
Если установки предоставляют разные форматы, коллектор выбирает самый новый
формат `pg_stat_statements`. Реализации `pg_store_plans` не ранжируются: при
наличии подходящего интерфейса выбирается текущая база, иначе выбор однозначно
определяет имя базы.

Формат `pg_stat_statements` выбирается по версии расширения. Семейство
`pg_store_plans` выбирается по сигнатурам функций и столбцам результата, а не по
`extversion`. Для OSSC, Datasentinel и vadv используются разные форматы.
Datasentinel добавляет к набору счётчиков OSSC идентификаторы отношений и тип
команды; vadv содержит внутренний `queryid`, поле `queryid_stat_statements` и
функцию получения плана по четырём ключам. Формат vadv пригоден только тогда,
когда то же расширение предоставляет доступный для немедленного вызова
преобразователь плана `text -> text`, который не возвращает набор. Коллектор в найденной схеме
оборачивает им функцию получения плана, а затем ограничивает результат 65 536
символами. Поэтому поле `plan` во всех поддерживаемых форматах содержит
ограниченный читаемый текст, а компактное содержимое расширения не выходит за
границу сбора PostgreSQL.

Небольшие служебные запросы используют Simple Query Protocol. Типизированные
метрики читаются одноразовыми безымянными запросами через Extended Protocol.
Запросы выполняются последовательно, без именованных prepared statements и
pipelining. Большие результаты читаются пакетами не более 256 строк с целевым
размером около 512 KiB декодированных прикладных данных. Последняя ограниченная
в SQL строка может превысить этот целевой размер. Пакет попадает в WAL до чтения
следующей строки. Текст запроса или плана ограничивается в SQL первыми 65 536
символами в каждом поле. Коллектор не выбирает top-N и не задаёт общий бюджет
текста.
При тайм-ауте запроса коллектор один раз отправляет ограниченный по времени
PostgreSQL CancelRequest, затем закрывает соединение.

До первой указанной версии PostgreSQL секции для `pg_stat_wal`, `pg_stat_io` и
`pg_stat_checkpointer` отсутствуют. В PostgreSQL 17 и 18 формат
`pg_stat_progress_vacuum` менялся, поэтому для этих версий используются
отдельные значения `type_id`. Каждая строка `pg_stat_progress_vacuum` также
несёт `schemaname`/`relname`, разрешённые из `pg_class`/`pg_namespace` тем же
запросом, которым коллектор читает представление; `relid` — это OID
`pg_class`, не переиспользуемый в горизонте, который важен продукту, поэтому
он остаётся идентичностью строки независимо от того, разрешилось ли имя. Имя
разрешается только для отношения в базе, к которой подключена сессия, — сессия
видит каталог только своей базы, — и в остальных случаях остаётся отсутствующим,
а не угадывается по строке другой базы. `pg_settings` хранит действующую конфигурацию
сессии, из которой коллектор читает метрики. Каждая строка называет базу и роль
подключения полями `datid`, `datname`, `usesysid` и `usename`; её идентификатор —
`(datid, usesysid, name)`. Проверочный запрос к серверу читает эти данные из
текущей сессии метрик. Представление читается в каждом цикле PostgreSQL и
записывается после первого успешного чтения, при изменении и в каждый новый
сегмент. Если между циклами PostgreSQL сегмент открывает другой источник,
используется последний успешный снимок.
Строки `primary_conninfo` и `ssl_passphrase_command` исключены: их значения могут
содержать секреты. Остальные командные и пользовательские настройки остаются в
снимке.
`pg_wal_storage` хранит одну точную сумму размеров обычных файлов, возвращённых
`pg_ls_waldir()`. Коллектор не читает вложенные каталоги и не определяет
назначение файлов по именам; без права на вызов этой функции секция отсутствует.
Секции отношений хранят действующий кластерный OID табличного пространства и
необязательное имя из каталога. Нулевой `reltablespace` разрешается через
фактический `dattablespace` подключённой базы, в том числе через нестандартное
пространство по умолчанию. У родителя секционированной таблицы без хранения нет
действующего размещения; строка индекса независимо хранит размещение самого
индекса. Размер таблицы по-прежнему включает основной fork heap и TOAST, но не
включает пользовательские индексы.

`pg_stat_statements` ниже 1.5 не собирается. Основная функция чтения
используется только тогда, когда текущая роль может использовать
`pg_read_all_stats`; доступное представление `pg_stat_statements_info`
выбирается независимо и без этой роли. Строки со скрытым из-за прав `queryid`
не имеют пригодного идентификатора и пропускаются. `pg_store_plans_info`
выбирается по точному формату доступного представления; интерфейс vadv такого
представления не содержит.
