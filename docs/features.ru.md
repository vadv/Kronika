# Экраны и элементы управления

Справочник описывает интерфейс этой ревизии исходного кода. Экран или поле появляется, когда
соответствующий источник и вариант структуры PostgreSQL есть в записи.

## Время, навигация и Inspector

| Элемент | Действие |
| --- | --- |
| Выбор дня/часа, предыдущий/следующий час | Выбирает один записанный календарный час. Горизонтальная шкала сохраняет весь час, даже если измерения есть только в его части. |
| Время браузера / UTC | Меняет отображаемое местное время и выбор часа. Записанные моменты не меняются. Для повторения ссылки и сравнения с логом другой машины удобно UTC. |
| Часы рабочей области | Выбранный момент курсора. Метрика показывает последнее измерение не позже него; периодичность разных источников может различаться. |
| Компактная шкала времени | Выберите метрику, наведите указатель для просмотра записанного момента и отпустите его для фиксации курсора. Уход без фиксации возвращает выбранное время. |
| Предыдущий/следующий записанный момент, ← / → | Переход между моментами, доступными текущему экрану, независимо от показанной линии. Это шаг по измерениям, а не по секундам. Элементы формы сохраняют собственное управление стрелками. |
| Обновить | Запрашивает новые записи и обновляет экран. Открытый текущий час также обновляется каждые 15 секунд; скрытая вкладка и исторические часы не опрашиваются. Старый час остаётся выбранным до перехода к другому. |
| График | Открывает выбранную метрику шкалы в Inspector. Выбор строки открывает объект, а его вкладка графика — собственную историю. |
| Детали / График / связанные вкладки Inspector | Переключает факты выбранной строки, историю и доступные связанные объекты. Набор вкладок зависит от строки. |
| Развернуть график / восстановить | Даёт графику Inspector больше места. Селектор метрики выбирает один показатель истории; у графиков с несколькими рядами есть подписи рядов и выбор всех. |
| Разделитель Inspector | Меняет ширину на настольном экране. При фокусе на разделителе стрелки меняют ширину, Home/End выбирают её пределы. |
| `?`, справка поля и Esc | `?` открывает общую справку; знак у поля — его определение. Esc закрывает открытую панель или выделение. |
| Выход | Завершает браузерную сессию живого web. Следующее посещение требует повторного входа. |
| Язык и тема | Немедленно переключает EN/RU и светлую/тёмную тему; выбор сохраняется в браузере. |
| Копировать точное значение | Копирует исходное значение, а не округлённое представление. Если автоматическое копирование недоступно, точный текст выделяется для ручного копирования. |

Легенда графика связывает цвет с рядом; наведение показывает значение, не
заменяя зафиксированный курсор. Last, Min, Max, P50, P90 и P99 описывают
записанные значения ряда. Это не перцентили времени отдельных запросов, если
сама метрика не имеет такого смысла. Длительность сохраняет знаменатель:
`мс/вызов` отличается от `мс/с`. Между измерениями не появляются выдуманные
точки. Пустой участок графика не означает линию нулей.

URL сохраняет курсор, экран, линзу, сортировку, поиск и поддерживаемое выделение
объекта. Назад/Вперёд в браузере восстанавливает навигацию. Обычный переход к
другой поисковой поверхности очищает её фильтр; переход по связи явно задаёт
поиск на целевом экране. Не все настройки находятся в URL: язык, тема,
раскрытие Activity и ширина Inspector сохраняются в браузере.

На телефоне кнопки графика и поиска открывают те же элементы в панелях;
список метрик шкалы становится обычным селектором. Inspector открывается снизу
на телефоне и поверх экрана на планшете, со своей прокруткой. Широкие таблицы
можно прокручивать. Это уменьшенная рабочая область для тех же данных,
а не отдельный набор мобильных метрик.

### Health, нагрузка и отметки

Линия Health отдельно показывает Overall, OS и PostgreSQL, когда они доступны.
OS Health вычитает из 100 наибольшую измеренную долю ожидания CPU/memory/I/O.
Используются соседние счётчики PSI `some_total` своей записанной области,
а не загрузка CPU или скользящее `avg10` ядра. OOM и throttled time остаются
отдельными показаниями. Без пригодных pressure-данных Health недоступен;
запись cgroup v1 не может подставлять host PSI вместо контейнерного.

PostgreSQL Health сравнивает active backends, включая ожидающие, с
`2 × KRONIKA_POSTGRES_EFFECTIVE_CPUS`. При числе не выше этой мощности он равен
100; выше неё вычитается `round(100 × (active − capacity) / active)`.
Настроенная мощность относится к наблюдаемой БД, которая может быть удалённой;
`max_connections` и CPU host коллектора не подставляются вместо неё.
Overall вычитает оба компонента и ограничивается 0–100. Выключенный PostgreSQL
ничего не вычитает; включённый без пригодного компонента оставляет Overall
недоступным. Health 100 описывает эти входные данные, а не все возможные
неполадки машины.

**Круги** шкалы обозначают события лога, **ромбы** — фиксированные пороги,
**треугольники** — резкие подъёмы. Справка выбранной метрики называет её точную
границу; отметки отделены от расчёта Health и цветов табличных значений.
[Полный список границ](../DESIGN.ru.md#опасные-границы) включает
CPU/memory/filesystem shares, load на online CPU, blocked sessions,
долгие запросы лога, возраст транзакций и рост явных счётчиков ошибок.

## Найти строку, выбрать линзу, прочитать историю

**Линза** выбирает колонки под определённый вопрос. Она не запускает сбор заново
и не меняет записанную строку. Заголовок сортируемой колонки меняет порядок.
Дерево процессов и цепочки блокировок сохраняют иерархию; сортировка есть не у
каждой колонки. Большие постраничные таблицы предлагают загрузить ещё строки
или повторить неудачный запрос. Во время загрузки или ошибки старые строки
могут оставаться с явным статусом: прежде чем считать их новым ответом,
прочитайте этот статус.

Поиск поддерживает обычный текст, `field:value`, `field>quantity`,
`field<quantity`, заглавные `AND`/`OR` и скобки. Текстовые поля принимают `*` и
`?`, если это указано в справке. Значения с пробелами заключайте в кавычки.
Применение или Enter фиксирует всё выражение; удаляемые метки показывают
применённые условия. Ошибочный черновик сохраняет последний верный результат
и URL.

Примеры для соответствующих экранов:

```text
# Processes
command:postgres* AND rss>100MiB
pid:1234

# Activity
state:active AND wait_type:Lock

# Statements / Plans
query_id:123456789

# Tables / Indexes
schema:public AND size>100MB
```

Числа здесь иллюстрируют синтаксис, а не идентификаторы публичной записи.
Справка поиска перечисляет точные поля и копируемые примеры текущей таблицы.
Сравнения строго `>` или `<`, до сортировки и разбиения на страницы; `MB` —
десятичная единица, `MiB` — двоичная, скорость требует `/s`, регистр единиц
важен. Отсутствующие значения не становятся нулями. `NOT`, `>=` и `<=` не
поддерживаются. В группировках Tables/Indexes имена выбирают участников,
а числовые условия проверяют результат группы: соединяйте эти этапы через
`AND`; один `OR` не может смешивать их.

Выбор строки открывает Inspector. Детали сохраняют идентификаторы, записанный
текст и единицы; график позволяет выбрать временной показатель. Справочные
числа вроде приоритета планировщика или топологии не становятся графиками
только потому, что они числовые. Связанные кнопки переходят по записанному
идентификатору, сохраняя час и курсор. Они выбирают множество совпадений,
а не произвольную первую строку.

## Тепловые карты Activity: кто внёс вклад за час?

Раскройте заголовок Activity над поддерживаемой таблицей. Выбранная метрика
ранжирует весь час, включая объекты, которых уже нет в момент курсора.
Запрос начинается при раскрытии. Компактная карта показывает до восьми строк
рейтинга, остальные входят в Other. Полноэкранный режим предлагает Top
10/25/50/100, начальный лимит — 25.

| Значение/элемент | Смысл |
| --- | --- |
| Ячейки времени | Скорость изменения счётчика по записанным интервалам; для gauges — интервальные значения. Пустая ячейка недоступна, самая светлая заливка означает настоящий ноль. |
| Итог часа | Накопленное изменение счётчика; максимум gauge, кроме RSS процессов, где колонка называется **Среднее**. |
| Под курсором | Значение ячейки в момент курсора. Оно может отличаться от точечной скорости в таблице. |
| Total | Все объекты, включая не вошедшие в показанный рейтинг. Приглушённая полоса всегда использует собственный максимум независимо от общей/построчной шкалы. |
| Other | Total минус показанные строки. Это не дополнительный процесс или запрос. |
| Общая шкала | Одна шкала интенсивности для строк рейтинга и Other; позволяет сравнивать величины. |
| По строкам | Каждая строка использует собственный максимум. Видно время активности тихой строки, но одинаковый цвет разных строк не означает одинаковую работу. |
| Нажатие на ячейку | Перемещает курсор к последней микросекунде ячейки. Таблица затем выбирает записанные снимки не позже этого времени. |
| Нажатие на строку | Фильтрует таблицу по объекту или группе. Если в текущей ячейке значения нет, также переходит к самому активному записанному интервалу этой строки. |

В Processes одна строка объединяет все записанные PID с одной командой,
включая завершившиеся процессы. CPU time складывает время user и system:
одна CPU-секунда за секунду означает одно занятое ядро. Итог часа — время CPU,
а не средний процент.

RSS складывает резидентную память PID группы на каждом записанном снимке
процессов и усредняет по этим снимкам. Отсутствующий на записанном снимке
процесс ничего не добавляет. Это не пик и не среднее только за время его жизни.
Общие страницы могут входить в RSS нескольких процессов; сумма не означает
уникальный объём занятой физической RAM.

У большинства карт 60 ячеек за час; у Tables и Indexes — 12, поскольку
снимки отношений собираются раз в пять минут. Число ячеек не меняет рейтинг
часа. Байты PostgreSQL используют записанный размер блока, CPU процессов —
записанную частоту тиков. Если этих метаданных нет, соответствующая Activity
оставляет исходные количества и единицы, не придумывая байты или секунды.

| Карта Activity | Метрики |
| --- | --- |
| Processes | CPU time, RSS, Disk read bytes, Disk write bytes, Major page faults, Run delay |
| Statements | Execution time, Calls, Rows, Shared buffer read bytes, Shared buffer dirtied bytes, Temp buffer written bytes, WAL bytes |
| Plans | Execution time, Calls, Rows, Shared buffer read bytes, Temp buffer written bytes |
| Databases | Commits, Rollbacks, Read bytes, Temp bytes, Deadlocks |
| Tables | Rows changed, Rows read by seq scans, Heap buffer read bytes, Dead tuples, Autovacuum time |
| Indexes | Index scans, Index tuples read, Index buffer read bytes |
| Cgroup CPU | CPU time, Throttled time |
| Cgroup I/O | Read bytes, Write bytes, Read operations, Write operations |

Activity в Tables/Indexes следует выбранной группировке по объекту, схеме,
базе или tablespace. **В публичной записи 5 сентября есть известная ошибка
Plans Activity из-за повторяющихся записанных идентичностей планов.** Таблица
Plans и Inspector выбранного плана работают. Это ограничение примера,
а не обычная пустая карта.

## Processes: какая Linux-задача выполняла работу?

| Линза | Значения и назначение |
| --- | --- |
| Tree | Родительские связи, пользователь, PID, CPU и memory %, VSZ, RSS, терминал, состояние, время старта, накопленное время CPU и полная командная строка. Поиск оставляет предков для контекста. |
| CPU | User/system в эквивалентах ядер, ожидание планировщика, block-I/O delay, добровольные/вынужденные переключения контекста, текущий CPU, nice/priority/realtime priority и политика планирования. |
| Memory | RSS, виртуальная память, swap, minor и major page faults. |
| Disk | Байты чтения/записи хранилища, число системных вызовов, логические байты чтения/записи, отменённые записи и block-I/O delay. Чтение из page cache может увеличивать логические байты при нулевом чтении хранилища. |
| General | Родительский PID, реальный/эффективный пользователь, group ID, число потоков, терминал, exit signal и состояние. |

Компактные итоги рядом с линзами относятся ко всему снимку процессов,
а не только к видимым или найденным строкам. Tree/General показывают процессы,
потоки, runnable и PostgreSQL backends; остальные линзы — свои ресурсные
итоги. Для скорости CPU нужны совпадающие записанные PID и идентичность старта
процесса в соседних снимках. Без предыдущего измерения или доступного
per-process I/O получается `—`.

Выбранный процесс может открыть PostgreSQL Activity по точному PID. Связанная
панель показывает фактическое время Activity и базу, роль, приложение,
клиента, состояние, ожидание, SQL и времена. Выбирается ближайшая записанная
строка Activity этого PID; её время может отличаться от курсора процесса.
Имена пользователей берутся из записанной локальной таблицы коллектора.
Неразрешённый пользователь остаётся числовым UID.

## Host: какой ресурс и в какой области?

Таблица **USE** разделяет использование, насыщение и ошибки. Заполненная ячейка
— кнопка: раскрывает ресурс и выбирает метрику. Можно держать открытыми
несколько ресурсов. Заголовок подводит итог строк: наибольшая сравнимая доля
использования под курсором, ресурсы с ненулевым ожиданием за час и число
записанных ошибок/событий. Он не складывает несопоставимые единицы давления
и не превращает нагрузку в предписание.

### CPU и память

CPU раскрывает доли user+nice, system, interrupts, I/O wait, stolen и idle;
эквиваленты занятых ядер исключают idle и I/O wait. Доступная мощность —
записанное число online logical CPU. Здесь же load averages,
runnable/blocked tasks, context switches и CPU PSI. PSI описывает время
ожидания ресурса, utilization — выполнение работы: занятый CPU и ожидающая
задача — разные показания.

CPU Topology содержит logical CPU, socket/core и NUMA ID, модель и максимальную
частоту, а также записанные CPUFreq policies. Actual
frequency относится к policy; scaling frequency — отдельная заявленная или
запрошенная рабочая частота. Общая частота взвешивается по online CPU только
при совместимых записанных источниках actual frequency. Статический максимум
частоты не является текущим измерением.

Memory разделяет anonymous, file cache с buffers, reclaimable slab,
unreclaimable slab, free и остаточную память. Available — отдельная оценка
ядра, пересекающаяся с освобождаемой памятью: её нельзя прибавлять к этим
компонентам. Total, swap, активность swap, memory PSI и OOM kills дополняют
картину. График состава и выбранная метрика сохраняют собственные единицы
и историю.

### Хранилище и сеть

| Режим Storage | Что читать |
| --- | --- |
| I/O | Скорости байтов и операций чтения/записи, busy time, среднюю очередь, задержку чтения/записи и операции в работе. Средняя задержка — изменение времени операций, делённое на число завершений; без завершений будет `—`. Host I/O PSI относится ко всему host, а не к задержке устройства. |
| Filesystems | Точные mount point/root, источник, тип, идентичность устройства; total/available bytes и total/available inodes. Available не тождественно свободному месту, доступному привилегированному процессу. |
| Topology | Записанные связи partition→device и layered device→slave. Раскрывается записанная структура; Kronika не выводит происхождение bind mount и отсутствующие в sysfs связи. |

Устройства сохраняют `major:minor`. Выбор открывает точную строку и историю
метрик. Network показывает RX/TX bytes, packets, errors и drops по интерфейсам,
с историями, а также записанные link speed и duplex. Трафик относится к network namespace коллектора; один байт
loopback может попасть и в RX, и в TX.

### Когда коллектор работает в контейнере

Область определяет записанное окружение: наличие systemd cgroup не превращает
машину в контейнер. В записях machine нет Cgroups. В записях container отдельно
показаны **Container**, **Network namespace** и **Host**.

Container CPU/Memory/I/O/Threads описывают собственную cgroup коллектора.
CPU использует её эффективную quota/cpuset-мощность, если она записана;
иначе показывает занятые ядра без вымышленного процента. Memory использует
известный эффективный лимит либо просто байты. Throttling CPU, controller PSI
и OOM kills остаются в своей области. Threads — `pids.current`, число TID
включая главные потоки; локальный `pids.max` — отдельная настройка,
а не гарантированный эффективный лимит всей иерархии.

CPU и I/O раскрывают карты Activity; каждый ресурс контейнера открывает
записанную таблицу cgroups с непосредственно живыми процессами. Элементы
CPU, Memory, I/O и Threads меняют режим, строка открывает Inspector. Память
cgroup разделяет anonymous, file, slab, other kernel и остаток начисленной
памяти; её лимит не равен RAM host.

Инвентарь I/O сворачивает только слои, связанные точными записанными рёбрами
топологии внутри одной cgroup. Inspector показывает счётчики каждого
начисленного слоя как одно и то же I/O, а не их сумму. Mount point, источник,
имя устройства, физическое устройство и `major:minor` сохраняют узнаваемость
строки. То же устройство в другой cgroup остаётся другой строкой. Diskstats
контейнера не перечисляет все посторонние диски нижележащего узла.

## PostgreSQL: от инстанса к запросу и отношению

Навигация PostgreSQL следует выбранной записи. У установки только с OS нет
пустой панели БД; старый час с PostgreSQL остаётся доступен, даже если сбор
сейчас выключен. Поля расширений и отдельных версий появляются только там,
где записаны. Эти элементы не меняют настройки PostgreSQL, не отменяют
backend и не запускают VACUUM/EXPLAIN.

### Overview и Databases

Overview — сводная таблица инстанса. Строка соединяет значение за час,
мини-график, показание под курсором и раскрываемый график; записанные лимиты
показаны пунктиром. Доступны:

- Соединения и параллелизм: client backends, active/waiting, idle in
  transaction, oldest transaction/xmin и prepared transactions.
- Транзакционная работа: commits/rollbacks, tuples read/fetched/written
  и доля buffer hits.
- Ошибки и временные данные: block I/O time, temp bytes, deadlocks, checksum
  failures и abnormal session ends.
- WAL/checkpoints: созданный WAL, плановые/запрошенные checkpoints,
  записи буферов checkpoint/backend, архивированные сегменты/ошибки и
  переполнения WAL buffers. Размер каталога `pg_wal` — отдельное текущее
  значение с историей, не скорость генерации WAL.
- Пределы vacuum: возраст XID/multixact и workers относительно записанных лимитов.
- Buffer pool/I/O: evictions, повторное использование кольцевых буферов,
  relation extends, fsyncs и чтения vacuum-контекста, если они записаны этой версией.

Заголовок показывает записанные version, `max_connections`, `shared_buffers`,
`max_wal_size`, `checkpoint_timeout`, `autovacuum` и `track_io_timing`, а также
lifecycle и изменения настроек. Раскройте изменения и выберите одно для
перехода курсора. Это запись настроек, а не редактор. При выключенном
`track_io_timing` счётчики времени I/O PostgreSQL могут содержать настоящий ноль.

Databases разделяет backends, commits/rollbacks, sessions, операции с tuples,
buffer reads/hits, I/O times, temp files/bytes, conflicts, deadlocks и frozen
XID age по базам. Activity отвечает на вопрос о вкладе базы за час, а выбор
строки открывает истории полей.

### Activity и Locks

Activity показывает PID, базу/роль, SQL, query/transaction duration,
приложение, клиента, state и wait type/event. **System** включает системные
backends, **Idle** — простаивающие сеансы. Изначально оба выключены. Inspector добавляет backend type,
leader PID, Query ID, backend/state age и transaction xmin/xid ages.
Продолжительность idle — не время активного исполнения запроса. Смена
состояния и отсутствующие измерения не превращаются в непрерывную линию
работающего запроса.

Связанные Statements используют ненулевой Query ID. Process открывает Linux
контекст backend по PID. SQL в Activity — текст в момент снимка; Statements
— накопительная статистика нормализованного запроса, это разные объекты.

Locks сохраняет порядок цепочек: корни, ожидающие потомки, дополнительные
блокирующие PID и блокировки prepared transactions. Показаны query/application,
lock target/relation/type/mode, state, wait и начало ожидания. Строка
открывает полный список блокирующих и контекст. Поиск сохраняет структуру
цепочки; отсутствующий в логе SQL держателя не заполняется догадкой.
Цепочки снимка здесь и группы исторических lock-wait логов в Events
отвечают на разные вопросы.

### Vacuum

Vacuum показывает записанные эпизоды: database/relation, PID, Autovacuum или
Manual/other, фазу, seen/last-seen, время и число снимков в фазе, heap
progress/size/vacuumed, index cycles и поля соответствующей версии.
Эпизод остаётся видимым после завершения процесса. **At sample** означает,
что он записан в проходе сбора под курсором; **Last seen** — время последнего
наблюдения.

График прогресса — просканированная heap относительно её размера, а не доля
прошедшего времени выполнения. Проходы по индексам могут повторяться.
PostgreSQL 17+ добавляет обработанные индексы и память dead-item,
PostgreSQL 18+ — cost-delay time. Отсутствующее в структуре поле недоступно.
Записанный ноль задержки может означать выключенный учёт времени.

Выделение фазы фиксировано её именем: `truncating heap` предшествует попытке
AccessExclusiveLock; vacuum heap/index и очистка индексов — тяжёлые фазы.
Это отдельно от измеренной нагрузки. **No movement** означает три или более
подряд неизменных фазовых показаний, а не утверждение, что backend завис.
Панель Process показывает изменения CPU, storage bytes, block-I/O wait и
major faults совпавшего PID за записанный эпизод: используются последние
снимки не позже его границ и сравнение с просканированной heap PostgreSQL.
Backend ручного VACUUM мог выполнять другую работу в этом промежутке.

### Statements и Plans

![Statements Activity и Inspector запроса из записанного часа](images/statements.png)

| Линза Statements | Вопрос и поля |
| --- | --- |
| Execution | Какой нормализованный SQL накопил работу? Calls/s, execution time/s, mean time/call и rows/s с базой, ролью и Query ID. |
| Per call | Сколько работы на выполнение? Интервальное mean time, rows и buffer bytes/call, частота вызовов. |
| I/O | Shared-buffer reads/hits/hit share, dirties/writes, local reads и temporary reads/writes. Промах буфера PostgreSQL может обслужить page cache ОС. |
| Resources | WAL bytes и bytes/call, temporary writes, planning time/share и execution/call rates. |
| Stability | Записанные mean/min/max/standard deviation и коэффициент вариации окна статистики, рядом с частотой вызовов. Это не заново вычисленные перцентили задержек выбранного часа. |

Запросы Kronika по умолчанию скрыты из строк Statements, рейтинга Activity
и сводки под общей областью workload. Переключатель **Запросы Kronika**
показывает точное число исключённых строк. Явный поиск, связанный контекст
или открытая строка коллектора включает все запросы и блокирует переключатель,
чтобы запрошенная строка не исчезла. Нормализованной идентичности могут
соответствовать несколько записанных строк базы/роли/top-level.

![Записанный текст плана в Inspector Plans](images/plans.png)

| Линза Plans | Поля |
| --- | --- |
| Execution | Первая строка текста плана, база/роль, Query ID или Related Query ID, Plan ID, calls/s, execution time/s, mean time/call и rows/s. |
| Timing | Записанные mean/min/max/standard deviation, частота вызовов и первый/последний вызов, если расширение их предоставляет. |
| I/O | Shared reads/hits/hit share, buffer bytes/call, shared dirties, local reads и temporary reads. |
| Identifiers | Plan/query IDs, тип команды, накопленные вызовы и частота вызовов. |

Inspector плана показывает записанный читаемый текст с отступами;
EXPLAIN повторно не запускается. Ссылки Query/Plan ID открывают совпадающие
Statements/Plans в том же часе под тем же курсором через видимый поиск.
Структура vadv отдельно показывает ненулевой связанный идентификатор
statement; внутренний ноль не является пригодным Query ID. Панель Query
получает связанный записанный SQL. Копирование сохраняет записанный текст;
ограничение длины при сборе остаётся видимым. Разные варианты расширения
не создают полей, которых в записи не было.

### Tables и Indexes

У обоих экранов есть группировки **объект, schema, database и tablespace**.
Группа имеет историю метрик и число участников; раскройте участников,
затем объект. Ссылки Table→Indexes и Index→Table сохраняют контекст отношения.
Проценты групп пересчитываются из исходных величин, а не усредняются по
объектам. Фильтр размера группы применяется к суммарному размеру группы.

| Линза Tables | Что доступно |
| --- | --- |
| Access | Tuple throughput, доля sequential scans, sequential/index scans, tuples per scan и последние времена scans. |
| Changes | Insert/update/delete и их доли, HOT/new-page updates, оценка dead share, изменения после analyze и вставки после vacuum. |
| Maintenance | Число ручных/автоматических vacuum и analyze, средние длительности там, где записаны, последнее обслуживание и TOAST autovacuum. |
| Size and buffers | Main-fork плюс TOAST, доли компонентов, оценки строк/dead TOAST, heap/index/TOAST buffer-hit shares. Это не сумма всех forks и индексов таблицы. |
| Freeze | Frozen XID/multixact ages, вставки после vacuum и последние времена vacuum. |

| Линза Indexes | Что доступно |
| --- | --- |
| Usage | Scans, tuples read/fetched, entries/fetches per scan, access method, tablespace и последнее сканирование. |
| Low activity | Размер, записанные scans и последний scan, число объектов без scans в группах. Тихий записанный интервал сам по себе не означает, что индекс можно удалять. |
| Size and buffers | Main-fork size и buffer-hit share; Inspector/история добавляет соответствующие записанные buffer fields. |
| State | Valid/ready, primary/unique/exclusion; группы подсчитывают эти свойства. |

Inspector индекса содержит записанное определение. Оценки числа строк таблицы
сохраняют приблизительный смысл; `Never` отличается от недоступного времени.
Эти экраны используют пятиминутные снимки отношений, а не трассу доступа
каждого запроса. Упоминание таблицы в SQL — направление для дальнейшего
просмотра, а не установленная связь учёта затрат statement.

## Events: читать логи рядом с метриками

Events соединяет сводку часа, отметки метрик и сгруппированные логи.
Уровни critical/notable/routine фиксированы типом события и задают порядок
и начальное раскрытие. Раскройте группу для её структуры; **Открыть характерное
событие** загружает одну полную записанную строку в Inspector. Кнопка времени
перемещает курсор. Характерное событие — не все участники группы.

| Источник | Группировка и полезные значения |
| --- | --- |
| PostgreSQL errors | Severity, category и нормализованный шаблон сообщения; число, первое/последнее появление и записанные подробности. |
| Slow queries | Нормализованный шаблон statement; число, максимальная и накопленная длительность. Характерное событие — самое медленное. Записанный порог логирования объясняет, какие запросы попали в источник. |
| Autovacuum/autoanalyze | Отношение; число запусков, длительность и записанные tuple/buffer details. |
| Checkpoints | Одна группа с плановыми/запрошенными checkpoints, buffer writes и sync time. Checkpoint warnings сохраняют записанный интервал. |
| Lock waits | Записанные holder PIDs; ожидающие сеансы и максимальное ожидание. Совпавшие acquired записи соединяются по PID/target; не сопоставленные завершённые ожидания остаются отдельно. |
| Lifecycle | Отдельные crash, shutdown и ready. |
| PgBouncer | Level и точное сообщение с общим database/user/client/file-контекстом. Буквальные `(nodb)` и `(nouser)` видны с пояснениями. |

Минутные полосы частоты перемещают курсор. Кластер шкалы выбирает точный
интервал и представленные источники логов; очистка возвращает целый час.
Числа строк лога, пересечений порогов и резких подъёмов разделены.
Событие лога с пороговой отметкой остаётся одной строкой лога. Ограниченный
результат сохраняет предупреждение, даже если локальный поиск сузил группы.

Форма маркера различает лог, фиксированный порог и резкий подъём; справка
объясняет метрику и границу. Выделение показывает, куда посмотреть, но не
утверждает причинную связь. Обычный рост работы не становится автоматически
ошибкой. У групп PgBouncer нет отметок на общей шкале. Temporary-file log
доступен через Events occurrences/MCP и детали строки, но не является
группой или отметкой шкалы этой консоли.

## MCP и панель подключения AI

**Подключить AI-агента** открывает `/mcp` того же web-сервера и готовые
подсказки настройки Claude Code, Codex и Cursor. Копирование использует
текущий язык интерфейса. Подсказка может содержать данные входа web;
обращайтесь с ней как с паролем. Панель подключает внешний клиент, а не
открывает встроенный чат, автоматически отправляющий час наружу. Подробнее:
[подключение MCP-клиентов](mcp-clients.ru.md).

| Инструменты | Вопрос к записи |
| --- | --- |
| `kronika_get_instance` | Последние записанные сведения host/PostgreSQL. |
| `kronika_list_recorded_sections` | Границы времени, доступные секции, поля, единицы и источники. |
| `kronika_rank_metrics` | Рейтинг одной или нескольких метрик за `[from,to)`. Каждое поле — отдельный результат; gauges ранжируются по максимуму, в том числе RSS здесь. |
| `kronika_find_processes` | Linux-процессы в одном записанном моменте. |
| `kronika_find_postgresql_activity`, `kronika_find_postgresql_locks`, `kronika_find_postgresql_vacuum` | Backends, locks и vacuum в записанном моменте. |
| `kronika_find_postgresql_databases`, `kronika_find_postgresql_statements`, `kronika_find_postgresql_plans` | Метрики БД/запросов/планов в записанном моменте. |
| `kronika_find_postgresql_tables`, `kronika_find_postgresql_indexes` | Отношения и поддерживаемые группировки в записанном моменте. |
| `kronika_find_events` | Группы или отдельные события за `[from,to)`. |
| `kronika_get_row_detail` | Полная записанная строка по непрозрачному `detail_ref` из другого инструмента. |

Для старого часа используйте записанные границы: `now` означает время запроса,
а не последний снимок. Передавайте `detail_ref` без изменений. Рейтинги и
поиск возвращают компактные результаты; детали строки дают SQL, планы
и логи. Инструменты возвращают показания, а не команды host, операции БД
или инструкции изменения production.

## Экспорт и автономные утилиты

**Экспорт** в верхней панели создаёт интерактивный HTML из собственных
записей. Этот час и ±5/15/30 минут используют текущий контекст; даты и время
начала/конца, сдвиги на час и длительность видны до запуска. Browser/UTC
действует для ввода; повторившееся местное время предлагает первое/второе
вхождение. Файл содержит все записанные секции интервала, а не только
выбранную линзу или фильтр.

Подготовка показывает прошедшее время, скачивание — полученные байты.
Активную подготовку нельзя отменить или запустить заново из диалога.
После сохранения показаны имя, размер и затраченное время. Файл содержит
интерфейс, WASM-движок запросов и данные и открывается без сервера.
WASM работает в основном потоке браузера. Замороженный диапазон не может
обновляться или предоставлять живой MCP endpoint. Записанные SQL,
командные строки и логи входят в файл; передавайте запись тем, кому она
предназначена.

Для командной строки `kronika-dump` перечисляет и читает содержимое сегмента
и умеет выделить ограниченный ZMS-интервал; `kronika-report` превращает
запись в самостоятельный HTML. Упаковка и примеры команд —
[в руководстве по выпуску](releases.ru.md). `kronika-demo` — необязательный
генератор нагрузки/пример, а не необходимый коллектор для своей машины.

Справочники метрик описывают поля хранения:
[Linux](type-registry/os.ru.md),
[PostgreSQL](type-registry/postgresql-metrics.ru.md) и
[PgBouncer](type-registry/pgbouncer.md). [Дизайн](../DESIGN.ru.md)
описывает контракты записи и вычислений.
