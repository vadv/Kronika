# kronika-collector

[English version](README.md)

`kronika-collector` читает метрики операционной системы с заданными интервалами
и записывает сегменты Kronika. Публичного интерфейса командной строки нет;
коллектор настраивается переменными окружения.

## Настройка

До первого сбора демон один раз читает и разбирает все переменные ниже. Если
значение не удаётся разобрать, демон останавливается и сообщает имя переменной
и неверное значение. Значение по умолчанию не подставляется.

Число строк от одного источника не ограничено. Источник возвращает все доступные
строки. Каждая запись `segment_write_finish` в логе содержит `rss_kib` — пиковый
размер резидентной памяти процесса.

Обязательна только переменная `KRONIKA_OUT_DIR`.

### Хранилище

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `KRONIKA_OUT_DIR` | — | Корень данных: журнал, готовые сегменты и блокировка записи. |
| `KRONIKA_SEGMENT_MAX_BYTES` | 64 MiB | Записать открытый сегмент, когда журнал накопит столько необработанных байтов. |
| `KRONIKA_SEGMENT_MAX_AGE_S` | 900 | Записать открытый сегмент по истечении этого времени, даже если предел байтов не достигнут. |
| `KRONIKA_JOURNAL_MAX_BYTES` | 1 GiB | Жёсткий предел `active.wal`. При его достижении открытый сегмент записывается досрочно, а добавление не завершается с ошибкой. |
| `KRONIKA_RETENTION` | 2 GiB | Целевой размер всего дерева для ротации: бюджет в байтах, `auto` (= `auto:80`) или `auto:P` для целевой доли занятого места на разделе, где хранятся данные. |

### Интервалы сбора

Планировщик отслеживает интервал каждого источника отдельно. Он ждёт не более
`KRONIKA_INTERVAL_S` и возобновляет работу раньше, когда наступает время опроса
источника. При интервале `0` источник читается в каждом цикле таймера.

| Переменная | По умолчанию, с | Секции |
| --- | ---: | --- |
| `KRONIKA_INTERVAL_S` | 5 | Максимальное время сна таймера; `0` отключает таймер, и сбор запускают только сигналы. |
| `KRONIKA_OS_CORE_INTERVAL_S` | 10 | `1_102`–`1_111`, `1_114`–`1_120`. |
| `KRONIKA_OS_MOUNTTOPO_INTERVAL_S` | 60 | `1_112`, `1_113`. |
| `KRONIKA_OS_PROCESS_INTERVAL_S` | 5 | `1_100`. |
| `KRONIKA_OS_PROCESS_STATUS_INTERVAL_S` | 30 | `1_101`. |
| `KRONIKA_OS_CGROUP_INTERVAL_S` | 10 | `1_201`–`1_204`. |
| `KRONIKA_OS_CGROUP_MAPPING_INTERVAL_S` | 30 | `1_200`. |
| `KRONIKA_PG_INTERVAL_S` | 30 | `1_001`–`1_010`, `1_012`, `1_019`. |
| `KRONIKA_PG_RELATIONS_INTERVAL_S` | 300 | `1_013`, `1_014`. |

### С какого сервера собирать метрики

Секции с метриками `PostgreSQL` собираются с сервера, указанного первым в
`KRONIKA_PG_DSNS`. В строке метрик нет столбца с именем сервера-источника.
Поэтому по остальным DSN коллектор читает только логи, а при запуске с
несколькими DSN пишет в лог одну строку о том, какой сервер выбран.

Статистика по таблицам и индексам доступна только в базе данных, которая её
сформировала. Поэтому коллектор открывает по одному соединению с каждой базой и
пересоздаёт его через час. В каждом таком цикле он заново читает список баз:
созданные после предыдущего цикла базы начинает собирать, удалённые — перестаёт.

`pg_stat_statements` собирается начиная с версии расширения 1.5. Для
`pg_store_plans` коллектор поддерживает OSSC версии 1.9 и новее, а также форк
vadv версии 2.x. Если поддерживаемой версии нет, соответствующие секции не
создаются. За один запрос коллектор выбирает 500 самых затратных планов и не
более одного мебибайта их текста.

Каждый сегмент содержит полный снимок `pg_settings`, поэтому по отдельному
сегменту видно, при каких настройках получены записанные в нём значения.

### Другие параметры

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `KRONIKA_LOG_LEVEL` | `info` | Одно из значений: `error`, `warn`, `info`, `debug`, `trace`. |
| `KRONIKA_PROC_ROOT` | `/proc` | Точка монтирования procfs. При другом пути обнаружение контейнера также ограничивается cgroup-файлом под этим корнем. |
| `KRONIKA_SYS_ROOT` | `/sys` | Точка монтирования sysfs. |
| `KRONIKA_STATVFS_FIXTURE` | не задано | Параметр для тестов: использовать значения ёмкости `path=TOTAL:FREE;...` вместо вызова `statvfs`. |

Ёмкость файловой системы запрашивается только для `ext2`, `ext3`, `ext4`, `xfs`,
`btrfs`, `f2fs`, `zfs`, `tmpfs` и `overlay`. Для сетевых, FUSE/userspace,
`autofs` и неизвестных типов файловых систем поля ёмкости остаются без
значений. Один вспомогательный процесс обрабатывает все разрешённые точки
монтирования с общим тайм-аутом в одну секунду, поэтому заблокированный запрос
ёмкости не останавливает последующие снимки.

## Запуск коллектора

```sh
KRONIKA_OUT_DIR=/var/lib/kronika kronika-collector
```

`SIGTERM` и `SIGINT` останавливают цикл и оставляют журнал на месте, чтобы после
перезапуска восстановить собранные данные. `SIGUSR2` немедленно собирает одно
окно, не дожидаясь следующего срабатывания таймера.
