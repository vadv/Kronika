# kronika-web

[English version](README.md)

`kronika-web` отдаёт записанные данные Kronika: встроенный одностраничный
интерфейс для людей и MCP-эндпоинт для LLM-клиентов. Он читает готовые
сегменты и корректный префикс `active.wal` через `kronika-reader`, открывает
каталог данных только на чтение и не держит кеш между запросами. Публичного
интерфейса командной строки нет; сервер настраивается переменными окружения.

## Настройка

Каждая переменная читается один раз, при старте. Значение, которое не
разбирается, останавливает сервер с сообщением, называющим переменную и
неверное значение.

| Переменная | По умолчанию | Значение |
| --- | ---: | --- |
| `KRONIKA_OUT_DIR` | — | Корень данных, который пишет коллектор: журнал, готовые сегменты и производные индексы. |
| `KRONIKA_WEB_LISTEN` | `127.0.0.1:8080` | Адрес сокета, который слушает HTTP-сервер. |
| `KRONIKA_WEB_SOURCES` | — | Десятичная битовая маска семейств источников в производных индексах: `1` — OS, `2` — PostgreSQL, `3` — оба. |
| `KRONIKA_WEB_USER` | — | Имя пользователя Basic-аутентификации; непустое, обязательно даже при выключенной аутентификации. |
| `KRONIKA_WEB_PASSWORD` | — | Пароль Basic-аутентификации; непустой, обязателен даже при выключенной аутентификации. |
| `KRONIKA_WEB_AUTH` | `required` | `required` требует аутентификацию на `/api` и `/mcp`; `disabled` пропускает каждый запрос. |
| `KRONIKA_WEB_COOKIE_SECURE` | `false` | `true` помечает сессионную куку браузера как `Secure` — для работы за TLS. |
| `KRONIKA_WEB_DEMO` | не задана | Единственное допустимое значение — `synthetic`: помечает каталог и интерфейс бейджем синтетического демо. Данные по-прежнему берутся из `KRONIKA_OUT_DIR`. |

## Запуск

```sh
KRONIKA_OUT_DIR=/var/lib/kronika \
KRONIKA_WEB_LISTEN=0.0.0.0:8080 \
KRONIKA_WEB_SOURCES=3 \
KRONIKA_WEB_USER=kronika \
KRONIKA_WEB_PASSWORD=secret \
kronika-web
```

При успешном старте процесс печатает `ready <addr>` в stdout и обслуживает
HTTP/1.1 до остановки.

Аутентификация принимает либо заголовок `Authorization: Basic`, либо
сессионную куку браузера, выданную `POST /auth/session`. Запрос с неверными
или отсутствующими учётными данными получает `401`.

## Эндпоинты

- `/` — интерфейс, один самодостаточный HTML-документ, встроенный в бинарник
  при сборке.
- `/auth/session` — вход из браузера: `GET` проверяет, `POST` с
  Basic-учётными данными выдаёт куку, `DELETE` очищает её.
- `/api/*` — JSON- и NDJSON-API интерфейса, только `GET`. Ответы несут
  `ETag` и учитывают `If-None-Match` и `Accept-Encoding`.
- `/mcp` — MCP-эндпоинт: Streamable HTTP без сессий, `POST` с
  JSON-ответами, только инструменты. Четырнадцать инструментов читают
  записанное — ранжирование по интервалу, каталог секций, метаданные
  инстанса, поиск по секциям, детали строки, события — и никогда не
  обращаются к наблюдаемой машине. Запросы с заголовком `Origin`
  отвергаются, поэтому браузер вызвать эндпоинт не может. Настройка
  клиентов: [docs/mcp-clients.ru.md](../../docs/mcp-clients.ru.md); панель
  MCP в верхней панели интерфейса выдаёт готовый к вставке промпт
  настройки.
