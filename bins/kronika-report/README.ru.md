# kronika-report

[English version](README.md)

Создаёт один самодостаточный интерактивный HTML-отчёт из одного готового
автономного ZMS. Запустите собранный бинарный файл; web и база данных не нужны:

```sh
./kronika-report incident.zms incident.html
```

`kronika-report --version` печатает `kronika-report 1.0.0` и завершает
работу без чтения конфигурации, обращения к хранилищу и запуска сервисов.
Права root не нужны; передайте `--version` единственным аргументом.

Входной файл может иметь любое имя с расширением `.zms`. Команда проверяет его,
получает внутренний идентификатор сегмента из каталога ZMS, строит канонический
IDX и атомарно заменяет выходной HTML. Сопутствующие файлы не создаются; корень
хранилища и предыдущий сегмент не нужны. Первая скорость, для которой нужен
более ранний отсчёт, остаётся `null`.

HTML содержит основной интерфейс на React, движок `kronika-query` на Rust,
скомпилированный в WebAssembly и работающий в браузере, ZMS и его
канонический IDX. Откройте файл прямо в обычном браузере. Таблицы, heatmap,
поиск и графики работают локально, без внешних ресурсов и сетевых запросов.
В автономном интерфейсе нет аутентификации, MCP, живого обновления и кнопки
повторного экспорта.

## Точный интервал отчёта

[Готовый срез ZMS](../kronika-dump/README.ru.md#срез) может содержать соседние
отсчёты для вычислений. Чтобы ограничить навигацию отчёта нужным интервалом,
передайте `--from` и `--to-exclusive` перед двумя путями:

```sh
./kronika-report --from 1788634800000000 --to-exclusive 1788638400000000 \
  incident.zms incident.html
```

Это ровно **19:00–20:00 UTC** 5 сентября 2026 года: полуоткрытый интервал в
Unix-микросекундах. Обе границы должны быть положительными целыми числами,
точно представимыми в JavaScript. Без них навигация использует весь диапазон
ZMS. Соседние отсчёты остаются доступны для вычислений, но не добавляют часы
в календарь отчёта.

Кнопка **«Экспорт»** в web создаёт такой же HTML прямо из каталога хранилища и
автоматически передаёт выбранный интервал.
